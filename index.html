§1 · The Problem

The typical LLM-based control loop

The standard LLM planning-and-control loop is simple, but its structure imposes limits that prevent real-time, adaptive behavior:

  1. High latency. The robot must wait for a full inference cycle before executing any action, making real-time responsiveness difficult.

  2. Blocking execution. The pipeline stalls during inference — the robot cannot react to new observations or interrupts mid-cycle.

  3. No speculative execution. Actions cannot be pre-fetched or pipelined; the robot idles while the model is thinking.

  4. Sequential, single-threaded planning. Only one planning request is handled at a time, preventing concurrent pursuit of multiple goals.

  5. Context-window bottleneck. All observations, memory, and system descriptions must fit a single prompt, limiting the richness of state that can be represented.

§2 · The Method

An asynchronous multi-agent architecture

Each agent runs at its own independent update frequency, directly addressing every limitation of the typical loop.

i.

Low-latency action execution

Reactive agents operate at high frequency without waiting on slow inference, enabling immediate responses to environmental change.

ii.

Non-blocking pipeline

Observation, planning, and execution run concurrently rather than in sequence, keeping the robot continuously active.

iii.

Speculative action pipelining

The planner issues upcoming actions ahead of time, so the robot executes them the moment the current action completes — minimal idle time.

iv.

Concurrent multi-task handling

Independent agents manage multiple goals at once, with a priority-based scheduler arbitrating between them in real time.

v.
Remark

Distributed context management

Each agent maintains its own focused context, avoiding the single-prompt bottleneck and allowing richer, more specialized representations of state.

§4 · Exception Handling

Handling the unexpected

Because every agent runs asynchronously, the robot copes with interruption two ways — deliberately switching between tasks, or reacting to a sudden event in an instant and then resuming.

Deliberate
Switch between tasks

A person enters the scene, so the robot deliberately sets its current task aside, attends to the new priority, and switches context — a scheduled, arbitrated hand-off between goals.

Reactive
React fast & resume

A sudden external event triggers a reflexive, low-latency response — the robot reacts and plays with the ball in real time, then resumes what it was doing without a full planning cycle.
